\section{Overview}

litefont is a small text rendering library: it turns OpenType fonts into crisp text. It reads the font file itself, renders hinted glyph images with exact antialiasing, lays out paragraphs and labels, and draws them through whichever graphics API a program uses (OpenGL 1.1, an OpenGL 3.3 core profile, Direct3D 11) or into an image on the CPU. It is written in C++20; its core depends only on the standard library, and each graphics API sits behind one device class, so no extension loader or other library is needed.

\begin{itemize}
	\item \textbf{Fonts:} TrueType and CFF (\texttt{.otf}) outlines, collections (\texttt{.ttc}), kerning from GPOS or the kern table, names and traits; damaged files fail cleanly.
	\item \textbf{Families:} regular, bold, italic and bold italic faces, simulated when missing; fallback families for missing code points; a catalog that finds families by name in a folder.
	\item \textbf{Glyphs:} exact-area coverage with vertical hinting; outlines, sharp and blurred shadows, all cached in a texture atlas; gradients with a color in each corner.
	\item \textbf{Layout:} wrapping, alignment, tabs, letter spacing, line limits with an ellipsis, superscripts and subscripts, underline and strikethrough, per-range colors and styles, anchors and quarter-turn rotation.
	\item \textbf{Editing queries:} caret boxes, selection rectangles, hit tests and caret movement.
\end{itemize}

\section{Quick start}

Every program does the same three things: it declares a font, the device for its graphics API and a painter that draws through the device; it loads the font once; and it calls \texttt{drawText} wherever it already draws.

\subsection*{OpenGL}

\texttt{OpenGL11Device} draws in any compatibility context, next to \texttt{glBegin} and \texttt{glEnd}; \texttt{OpenGL33Device} draws in a 3.3 or newer context, core profiles included. Either can be declared before the context exists: it finds its OpenGL functions and makes its textures at the first draw, so no loader is needed.

\begin{lstlisting}
#include <litefont/litefont.h>

litefont::Font font;                       // (1) declare
litefont::OpenGL11Device device;           // or OpenGL33Device
litefont::TextPainter painter(device);

void init() {
	font.load("NotoSans-Regular.ttf");     // (2) load once
}

void display() {
	glBegin(GL_TRIANGLES);                 // the program's own drawing
	// ...
	glEnd();
	painter.drawText(font, 16.0f, "Hello world", 20.0f, 40.0f);   // (3) draw
}
\end{lstlisting}

\subsection*{Direct3D 11}

\texttt{D3D11Device} draws with the program's own Direct3D device and context, into whatever render target is bound and in its first viewport. It can be declared before Direct3D exists and attached once the program has made its device; it makes its shaders, states and textures at the first draw.

\begin{lstlisting}
#include <litefont/litefont.h>

litefont::Font font;                       // (1) declare
litefont::D3D11Device device;
litefont::TextPainter painter(device);

void init(ID3D11Device* d3d, ID3D11DeviceContext* context) {
	device.attach(d3d, context);           // once Direct3D exists
	font.load("NotoSans-Regular.ttf");     // (2) load once
}

void render() {
	context->OMSetRenderTargets(1, &target, nullptr);
	context->RSSetViewports(1, &viewport);
	// ... the program's own drawing ...
	painter.drawText(font, 16.0f, "Hello world", 20.0f, 40.0f);   // (3) draw
	swapChain->Present(1, 0);
}
\end{lstlisting}

Positions are pixels from the top-left corner of the viewport. \texttt{measureText} gives the box a string takes, for centering or right alignment, and \texttt{setScale} sets the device pixels per pixel on high-density screens. The same painter also draws on the CPU: with a \texttt{SoftwareDevice}, the program calls \texttt{beginFrame} with a size and a clear color before drawing, and \texttt{readPixels} afterwards to take the image.

A \textbf{Font} owns its file's bytes and answers questions about them: metrics, the glyph for a code point, advances, kerning and outlines. \textbf{TextLayout} places the glyphs of a \textbf{Text} (its content, family, size, colors and layout settings) on whole-pixel baselines. The \textbf{GlyphRasterizer} renders each glyph at its size, hinted so baselines and x-heights land on whole pixels, and the \textbf{SpriteAtlas} keeps the images in texture pages. The \textbf{TextRenderer} turns placed glyphs into quads and hands them to a \textbf{GraphicsDevice}, the one interface every graphics API implements: \textbf{OpenGL11Device}, \textbf{OpenGL33Device} and \textbf{D3D11Device} on the GPU, \textbf{SoftwareDevice} on the CPU. All of them use the same blending and give the same pixels to within one level.

A Text is laid out once and kept. Drawing it again, or moving it, costs no layout and no glyph rendering; only a change to how it looks starts over.

\section{Devices and drawing}

\texttt{TextPainter} is the immediate front end, over any device. Each \texttt{drawText} call draws at once, in call order with the program's own drawing. Behind it, every distinct string with its font, size, style and color keeps its layout and glyphs, so a string drawn every frame, even at a new position, costs a lookup and moving its quads. The least recently drawn strings are dropped once the cache holds more than 1024. \texttt{draw(text, x, y)} does the same for a Text with all its own settings.

The program names its device once, where it declares it:
\begin{itemize}
	\item \texttt{OpenGL11Device} uses only OpenGL 1.1 fixed function, so it runs in any compatibility context, next to \texttt{glBegin} and \texttt{glEnd}. Glyph pages are alpha textures, modulated by the vertex color. It saves and restores the program's state with \texttt{glPushAttrib}, \texttt{glPushClientAttrib} and the matrix stacks.
	\item \texttt{OpenGL33Device} runs in 3.3 or newer contexts, core profiles included. It draws with one small shader from a vertex array and buffers, with one-channel glyph pages read as alpha. Core profiles have no attribute stack, so it reads each value it changes and sets it back afterwards.
	\item \texttt{D3D11Device} draws with Direct3D 11 into whatever render target is bound. The program hands it its \texttt{ID3D11Device} and context; its shaders are compiled ahead of time and built in, and it saves and restores every piece of pipeline state it sets.
	\item \texttt{SoftwareDevice} draws into an image in memory, the way a GPU does: the reference the others are checked against, and the device for tests and command-line rendering.
\end{itemize}
For each draw a GPU device sets what text needs (a projection, blending, the atlas texture, the scissor for clips) and switches off depth test and face culling. \texttt{setRestoreState(false)} skips saving and restoring for programs that manage their own state.

The devices stay out of each other's way. The OpenGL devices include no OpenGL header and need no loader: each finds its functions at the first draw through a table of them (\texttt{OpenGL11Functions}, \texttt{OpenGL33Functions}), and \texttt{OpenGLFunctions.cpp} is the only file that knows the operating system. \texttt{D3D11Device} calls Direct3D only through the objects the program gives it, so it links no Direct3D library, and its header declares the Direct3D interfaces without including a Windows header. Textures, buffers and shaders are made at the first draw; \texttt{release()} deletes them, and \texttt{getError()} says why a device drew nothing.

\subsection*{Text in the program's own transform}

By default text sits on the pixel grid of the viewport. To draw it in the program's own coordinates instead, such as a zoomable 2D view, a turning label or a point in a 3D scene, the program tells the device: \texttt{setMatrix(m)} takes a column-major matrix (projection times model-view, as a shader would) on any device, the CPU included, and on \texttt{OpenGL11Device}, \texttt{useMatrixStack()} draws through whatever the program set with \texttt{glOrtho}, \texttt{glRotatef} and the rest. \texttt{useViewport()} goes back to pixels.

\begin{lstlisting}
glMatrixMode(GL_MODELVIEW);
glRotatef(degrees, 0.0f, 0.0f, 1.0f);
device.useMatrixStack();
painter.draw(label);
device.useViewport();
\end{lstlisting}

Positions and sizes are then in the program's units, and text grows downward from its position; y is up by default, and \texttt{setYUp(false)} serves a y-down space. Each string is rendered at about the size it covers on screen, in steps of a sixth of an octave, and the matrix carries it the rest of the way with linear filtering, so text stays sharp at any zoom, and moving, turning or zooming it costs no new layout until its size crosses a step.

\section{Texts and labels}

A \texttt{Text} holds everything about how a piece of text looks. Changing a setting marks it for a new layout, except the offset and clip, which only move or cut what is drawn.

\texttt{TextCursor} answers the geometry an editor needs from a layout: the caret box, selection rectangles, the position a point hits, and where the caret moves by character, word or line.

\section{Fonts}

A \texttt{Font} loads a \texttt{.ttf}, \texttt{.otf} or one face of a \texttt{.ttc} file, from a path or from bytes in memory. A \texttt{FontFamily} groups up to four faces and simulates bold and italic where a face is missing; fallback families supply code points the family lacks, and the replacement character marks those nobody has. A \texttt{FontCatalog} reads only the names and traits of the fonts in a folder, from a few small reads per file, and loads a family by name. litefont never looks for system fonts by itself: it reads the files and folders a program names.

\section{Building}

litefont builds with CMake 3.20 or newer and any C++20 compiler; with CMake 3.21 or newer, its presets do the setup.
\begin{lstlisting}[language=bash]
cmake --preset default
cmake --build --preset release
\end{lstlisting}
That builds the library, its tests and the examples in \texttt{build/} (programs in \texttt{build/bin}, libraries in \texttt{build/lib}) and assembles \texttt{build/bin\_release}: \texttt{examples/} holds the example programs, ready to start with a double-click, with their DLLs and the open-source Noto fonts they ship with, and \texttt{sdk/} holds \texttt{include/} and \texttt{lib/} with the library and its CMake package. The \texttt{vcpkg} preset takes packages such as freeglut from \texttt{VCPKG\_ROOT}, and the \texttt{asan} preset builds with AddressSanitizer in \texttt{build-asan/}.

\texttt{LITEFONT\_OPENGL} and \texttt{LITEFONT\_D3D11} turn the GPU devices off; with both off, litefont depends on the C++ standard library alone. A project adds litefont with \texttt{add\_subdirectory}, or uses the SDK (or an install) with \texttt{find\_package(litefont)}; either way it links \texttt{litefont::litefont}.
